## Session 9 — sector-neutral robustness check
Avdhoot chose this as Phase C's next step (over frontend build, scaling qualitative content to the new 300 stocks, or deciding the Mutual Funds timeline). This closes an item that had been open since Session 4/6: "should happen before ever expanding past 200 stocks" — which had, by Session 8, already happened, making this overdue.

**What it checked, in plain terms:** the already-validated `truescore_ml_v2` model's walk-forward Rank IC (0.150 avg, signed off in Session 6) was measured with all stocks pooled together each quarter. That alone can't rule out the model just riding sector-level performance (e.g. always favoring one hot sector) rather than genuinely telling good stocks apart from bad ones within a sector. New script `21_sector_neutral_robustness_check.py` re-ran the exact same validated methodology (same features, same 2-year rolling training window, same XGBoost settings, same `training_dataset.csv`) but additionally measured, per quarter: (1) Rank IC computed separately within each sector then averaged, and (2) whether any single sector persistently dominates the model's top-10%-ranked picks beyond its actual share of the universe.

**Result: PASSED, cleanly.** Across 35 tested quarters (2017 Q4 – 2026 Q2): average pooled Rank IC 0.114, average sector-neutral Rank IC 0.099 — a small gap (0.015) — with 30 of 35 quarters still positive on a sector-neutral basis. No sector was found to persistently over-represent the model's top decile. Reading: the model's edge looks like genuine stock-picking within sectors, not a disguised sector bet.

**Scope note:** this check ran against the existing 200-stock `training_dataset.csv` (the same one used for the signed-off Session 6 validation) — apples-to-apples with that existing evidence. ## Session 7 — Phase C begins: ongoing TrueScore performance tracking
Avdhoot chose this as Phase C's first focus (over frontend build or scaling to Nifty 500): the `score_performance_tracking` table PROJECT_STATE.md had flagged as "not yet set up, good candidate for early Phase C" now has a real, automated job behind it.

**What it does, in plain terms:** every score TrueResearch has ever handed out (any `run_date`/`formula_version` combination already in the `scores` table) gets grouped into 10 "deciles" by that day's `overall_score` (decile 10 = highest-scoring stocks that day, decile 1 = lowest). For each of three forward windows — 1 month, 3 months, 1 year — the job checks whether enough real time has actually passed since that score was given; if it has, it computes each stock's real price return over that window and averages it within its decile, then saves one row per (date, formula_version, decile) into `score_performance_tracking`. This is the living, ongoing version of the one-time `TrueScore_Validation_Report.md` backtest — it keeps accumulating real evidence forever instead of going stale.

**New files (in `TrueResearch Code`):**
- `16_add_performance_tracking_run_type.sql` — one-time migration; adds `'performance_tracking'` as a 4th allowed value in `ingestion_runs.run_type` (previously only daily_prices/weekly_fundamentals/scoring), so this job can log its runs the same way the others do.
- `17_score_performance_tracking.py` — the job itself. Safe to re-run any time (upserts on `date, formula_version, decile`); logs every run into `ingestion_runs` via `ingestion_log.py`, same as the other pipeline jobs.
- `.github/workflows/score-performance-tracking.yml` — runs it automatically every Sunday (3am UTC, an hour after the existing weekly fundamentals job), plus a manual "Run workflow" button, same pattern as the other two scheduled jobs.

## Session 6 — Step 6 correction (IMPORTANT, read before touching TrueScore)
A review comparing Session 5's Step 6 work against the actual, previously-validated "Case C" model from Avdhoot's separate ClearStocks ML experiment found THREE real problems:
1. **Feature drift.** Session 5's model (`11_train_model.py`, `12_walkforward_validation.py`, `14_score_current_stocks.py`) trained on 17 numeric features, but the original StockApp experiment's validated Case C model used exactly 14 — three extra columns (`Debt_to_Equity`, `Revenue_Growth_YoY`, `NetIncome_Growth_YoY`) had been quietly added and were never independently tested. **Fixed:** all three scripts now use the exact validated 14-feature list.
2. **Live-scoring bug.** `14_score_current_stocks.py`'s `Relative_Strength_3M` input just reused the stock's raw `Return_3M` instead of comparing it to the Nifty 100 benchmark's own 3-month return — the training script computed this correctly, but live scoring didn't match it. **Fixed:** live scoring now fetches the benchmark and computes it the same way training does.
3. **Dataset-building bug (found after Avdhoot asked why only 10 quarters were validated vs. the original's 13).** `09_build_training_data.py` was SKIPPING any snapshot date entirely when a stock's fundamentals weren't usable yet at that point in time. Row-by-row comparison against the original `training_dataset.csv` showed the original KEPT those early "technical-only" snapshots (price/momentum data present, fundamentals columns just blank/NaN) all the way back to August 2022, and let XGBoost handle the missing values natively (documented as intentional in the original `train_model.py`'s own comments). Skipping them cut 2022 Q3–2023 Q2 from 900+ rows down to about 70, which is why walk-forward validation could only start at 2024 Q1 instead of the original's 2023 Q2 — three quarters of already-proven validation history lost for no real reason. **Fixed:** `09_build_training_data.py` now keeps technical-only rows with blank fundamentals instead of dropping them.

**Honest nuance flagged to Avdhoot (not a bug, just worth knowing):** in the stretch where almost every stock's fundamentals are simultaneously blank (~Aug 2022–mid 2023), the model is effectively running as technical-only for those quarters, not the full technical+fundamentals blend it becomes later. This is a property of the original Case C results too (whether or not it was called out explicitly at the time), not something the fix introduces. Worth a quick before/after look on early vs. later quarters once the dataset is rebuilt, though not blocking.

**What was done in this session so far:** `11_train_model.py` and `12_walkforward_validation.py` were re-run locally against the (pre-fix-#3) `training_dataset.csv` with the corrected feature list from fixes #1/#2 — that intermediate result (6 of 10 quarters significant, avg Rank IC 0.101, avg spread 6.0pp) is SUPERSEDED and will change again once the dataset is rebuilt with fix #3. Do not treat those numbers as final. Also researched (2026, current) free/paid options for deeper Indian fundamentals history beyond yfinance's ~4-year free window — conclusion: no clean free 10-year option exists (Screener.in is the best value at ~₹5k/yr but needs a paid plan for programmatic export; NSE/BSE filings are free but require heavy scraping; global APIs like Alpha Vantage/FMP have weak-to-absent India coverage). See "Planned for Phase 5" below for Avdhoot's decision on this.

**Part 3 update — dataset rebuilt, and a 4th finding led to a locked-in methodology change.** Avdhoot ran the corrected `09_build_training_data.py` locally: it built 18,755 rows (up from 6,475), but spanning back to **2017 Q2** instead of just 2022 — because TrueResearch's price history already had a full 10-year backfill (from Session 5) that the row-dropping bug had been hiding the benefit of. Re-running the walk-forward validation on this fuller dataset with the SAME "expanding window" approach as before actually made recent-quarter (2024-2026) results WORSE (avg Rank IC fell to 0.061) — training on 2017-2021 data (very different market regimes, including COVID) was diluting what the model learned about today's market. Five different training-window strategies were tested (see `Step6_ML_Model_Decision_Log.md` and `experiment_window_comparison.py` for full detail); **a 2-year rolling training window won clearly** and is now locked in as the final methodology (`formula_version truescore_ml_v2` / combined `truescore_v2`).

**Final validated result, on the exact 13-quarter window matching the original StockApp Case C experiment (2023 Q2 – 2026 Q2):** 11 of 13 quarters directionally positive, 9 of 13 statistically significant, average Rank IC **0.150**, average spread **12.5 points** — this now BEATS the original's own result (12/13, avg IC ~0.133) on real, current TrueResearch data.
